# tauri/

tauri/ Mac and iPhone apps built with Tauri: window/, a window onto the hosted site: plugin/, the Tauri plugin an app's shell builds, with desktop sign-in's shell half, the Mac menu bar (src/menu.rs) and updates from the app's releases (src/updates.rs), and the page half (index.ts), with the update line (lines.tsx), and the names both share (names.ts), and start/, the start page the window opens on, which waits for the site and says when it cannot reach it (start/index.html, the only file there, since an app's frontendDist names the folder); mac-release/, `app-kit mac release` (release.ts), which publishes a Mac release the installed app updates itself to, notarized when a Developer ID signs it, with this Mac's folder paths rewritten out of the build and searched for in what goes up (build-paths.ts), `app-kit mac watch` (watch.ts), which releases an app after each landing that changes it, `app-kit mac key` (key.ts), which makes the key that signs it, and what they read from the app (app.ts); watch-main.ts, what the Mac release watcher and the TestFlight watcher share: the pass under a lock, the clone main is fetched into and checked out in, which files count as the app, the record and the build logs; sign-in/, desktop sign-in through the browser (app-kit/tauri/sign-in), and its server routes (server.ts, app-kit/tauri/sign-in/server); iphone-notifications/, notifications through Apple's push service: the page half (index.ts), the sending (server.ts), the names both share with the plugin (names.ts), and plugin/, the Tauri plugin's Rust and Swift that an app's shell builds; apple-messages/, reading Apple Messages on the Mac: plugin/, the Tauri plugin's Rust that reads the Messages and Contacts databases under Full Disk Access (its tests read made-up ones), the page half (index.ts) with the catch-up and Messages Service's connect link, the names and upload limits the plugin, the page, an app's server and Messages Service share (names.ts), the server's routes the service connects and pushes texts to (server.ts), and in the plugin the service's installer (src/service.rs); iphone-sign-in/, Google sign-in in Apple's sign-in sheet: the page half (index.ts), the names it shares with the plugin (names.ts), and plugin/; iphone-run/, `app-kit iphone run sim|phone`, which builds an app and starts it on a Simulator or a paired iPhone, and points an agent at the README's section on tapping and looking at it; iphone-simulator/, the step `app-kit iphone-simulator quiet` runs, which sends a simulator's sound to BlackHole (index.ts), and how long a Simulator `iphone run sim` boots stays up and how many run at once, with its watcher and `app-kit iphone-simulator keep`, and the idle check `app-kit iphone-simulator shut-down-idle`, which shuts down a Simulator booted any other way once nothing uses it (lifetime.ts); testflight/, `app-kit testflight upload` (upload.ts) and `app-kit testflight watch` (watch.ts), with the App Store Connect calls, the key and the distribution certificate read from 1Password (key.ts, whose item readers the Mac release uses too), the signing with them and what Tauri leaves that is put back (signing.ts); apple-token.ts, the ES256 token Apple's push service and App Store Connect both take; build-env.ts, the environment every iPhone build and the Mac release's build run in, with no FORCE_COLOR; state.ts, the folder under ~/.local/state/app-kit each part keeps its state in, with its lock and log, which the TestFlight watcher and the Simulators' shut-down times share, and whose lock the TestFlight upload's one signing build at a time takes too; playwright.js, the Tauri bridge faked for apps' browser tests, with desktop sign-in's steps (app-kit/tauri/playwright)

## Rules for agents working here

- A Tauri plugin lives in the folder of the piece that uses it, as `plugin/`, and an app's shell builds it from the kit bun installed, by a Cargo path into `node_modules`, so `package.json` stays the one place that names the kit's version. Its `Cargo.lock` is committed, so the gates build pinned crates; what its build writes (`.tauri/`, `permissions/autogenerated/`, `permissions/schemas/`, Swift's build state) is ignored and made again by every build. A name its Rust, Swift and page share lives in the piece's `names.ts`, held by a test that reads the sources, since nothing here links the plugin into an app.
